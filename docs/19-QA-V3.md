# 19 · QA v3 时长缩放口径

> 解决的问题：v2 的固定阈值对长片不公平——180s 片天然累积更多静止段/硬切点，
> "断点数 ≤2 满分、≤4 八分"这类标准是按 8-50s 短片校准的，长片治理得再好也会被扣分。

## 一、公式

```
duration      = frames / fps
still_budget  = max(2, ceil(duration / 20))     # 每 20s 允许 1 个断点（静止段）
cut_budget    = max(6, ceil(duration / 15))     # 每 15s 允许 1 个硬切（至少 6）
```

| 项 | v2（固定） | v3（缩放） |
|---|---|---|
| 断点数量 | ≤2 → 10 / ≤4 → 8 / else 5 | ≤still_budget → 10 / ≤2×budget → 8 / else 5 |
| 切点节奏 | 2≤c≤6 → 10 / c≤9 → 8 / else 5 | 2≤c≤cut_budget → 10 / c≤1.5×budget → 8 / else 5 |
| 静止控制 | 最长静止段 ≤1.5/2.5/4s | **不变**（最长段与片长无关） |

预算示例：8s → 2/6，11.43s → 2/6，50s → 3/6，180s → 9/12。

## 二、兼容性（实测）

短片（≤20s）的两个预算恰好等于 v2 固定阈值，因此**历史分数逐项可比**：

| 片 | v2 | v3 | 差异 |
|---|---|---|---|
| demo-hook-compound 11.43s | 8.82 | **8.82** | 逐项相同（预算 2/6） |
| paper-shannon-deep 180s | 9.18 | **9.36** | 断点数量 8→10（3 个断点 / 预算 9） |

`--v2` 开关可回退旧口径做同帧对比；`analyze()` 像素计算完全没动，v3 只改评分函数。

## 三、报告可解释性

- stdout 打印 `QA 口径：v3 时长预算（180s → 断点≤9 / 硬切≤12）`
- JSON 报告新增 `qa_version`（`v2`/`v3`）与 `budgets`（duration / still_budget / cut_budget）

## 四、口径迁移说明

registry.json 与 docs 里**历史 QA 分数均为 v2 口径**。v3 起的长片分数不与历史直接横比；
需要对齐时用 `python pipeline/qa/qa_check.py frames --fps 30 --v2 --json qa_v2.json`。
门禁线 `avg < 8 → exit 1` 保持不动。

## 五、v4 只动检测、不动评分

v4（见 `docs/20-QA-V4.md`）沿用本节的时长预算评分，`score()` 逐项不变；它替换的是
边缘溢出的**检测口径**。开关语义：

| 命令 | qa_version | 评分 | 边缘检测 |
|---|---|---|---|
| 默认 | `v4` | 时长预算 | 画风感知（相对背景 + 面积门槛） |
| `--legacy-edge` | `v3` | 时长预算 | 绝对亮度线 `edge_max > 235` |
| `--v2` | `v2` | 固定阈值 | 绝对亮度线 `edge_max > 235` |

短片历史分数在三种口径下逐项相同（实测 demo-hook-compound 8.8 / project-vibeflow 9.1）。

## 二、零插件决策（明确表）

| 插件 | 能力 | 决策 | 硬理由 |
|---|---|---|---|
| `dsh-hyperframes` | HyperFrames 渲染器 + GSAP | **拒绝** | 引入第二渲染路径。flash 会在 `render(t)` 和 HyperFrames 的声明式 API 之间混用，渲出半截片且不自知 |
| `dsh-remotion` | React 视频 + 38 条规则 | **拒绝** | React 工具链 + 38 条 Remotion API 规则，与单文件 Canvas 零重叠，纯占上下文 |
| `dsh-ffmpeg` | 7 类 ffmpeg 工具 | **拒绝** | `build.ps1` 已覆盖，且自带 −14 LUFS 响度规范；多一条路径不受控 |
| `modlens` | 给纯文本模型补视觉 | **拒绝** | flash 自带图像理解，冗余 |
| `dsh-infinite_canvas` | 节点式短剧工作室 | **拒绝** | 剧情向工具，与知识片不是一类 |

### 为什么"少装"对 flash 特别重要

flash 有 1M 上下文，但**"能用"不等于"用得准"**：

- 上下文里每多一套 API，它混用的概率就上升
- flash 不会告诉你"我混了两套写法"，它会安静地渲出错误画面
- 你唯一的防线是**只有一条路径**——错得可预测，才好修

> 一句话：**强模型可以靠判断力在多个工具间选对的；flash 需要你替它把选择删掉。**

## 四、缺口（诚实清单）

| 缺口 | 影响 | 什么时候补 |
|---|---|---|
| 配音 TTS | 目前只有字幕，无旁白（纸金风本来就无旁白） | 要做口播时接第三方 TTS |
| `fable` 只有竖屏版 | 本项目只做横屏，这套规范得整段重排（已给初值，未验证） | 第一条心理/行为选题时 |
| 风格包只有 3 套 | 选题跨度大时不够 | 每做 5 条片沉淀 1 套 |
| 禁令只验证到"能过 9 分" | 没验证到"能到爆款密度" | 机制段加真运动后复测 |

> 竖屏：已于 2026-10-22 **明确放弃**（只做横屏 1920×1080），不再列为缺口。

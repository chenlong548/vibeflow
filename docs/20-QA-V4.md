# 20 · QA v4 画风感知边缘检测

> 解决的问题：v1–v3 的「安全区」用一条**绝对亮度线** `edge_max > 235` 判断内容溢出。
> 这条线是按深空冷底片校准的，遇到 paper 浅底片会同时**全帧误报**和**真溢出漏检**。
> 历史上项目片 QA 7.4 那一轮，是靠「加强浅底暗角把边缘亮度压到 232」绕过去的——
> 那是改艺术去迁就检测器。v4 从检测口径根治。

## 一、旧口径错在哪（实测档案）

边带 = 画面四边各 2.5%。取两条正式样片逐帧量化（背景 `bg` = 全片亮度中位数）：

| 片 | 画风 | bg | 边带亮度 | `edge_max` | 绝对线结果 |
|---|---|---|---|---|---|
| demo-hook-compound（343 帧） | 深空冷底 | 13.8 | q99 ≈ 14，偶发亮点 | 50–83 | 永远不报 |
| project-vibeflow（1500 帧） | paper 浅底 | 221.3 | q01 ≈ 197（暗角） | 恒定 232 | 取决于暗角 α |

两个方向都坏：

1. **深底 = 只抓纯白溢出**。背景 13.8，`edge_max` 最高才 83。一块中灰内容（L=140）
   贴到画面边缘，检测器完全无感；只有接近纯白的内容才会越过 235。
2. **浅底 = 正常帧误报 + 暗溢出全漏**。背景亮度 252 时，四边没有任何内容也恒过 235
   （历史档案：全部 1500 帧都过线，`edge_bleed[:10]` 只是显示截断，看起来像只报 10 帧）。
   反过来在左边带注入一块 deep teal 暗色字块后，`edge_max` **仍是 232，纹丝不动**——
   浅底上文字被切到边缘，旧门禁一个字都看不见。

一句话：**「亮于 235」既不是溢出的充分条件，也不是必要条件。**

## 二、v4 口径

```
bg    = median(全片每帧平均亮度)                 # 画风基线，全片一次
style = 'dark'  if bg < 128 else 'light'

边带异常像素（四边各 2.5%）:
  dark :  L > bg + 96         # 深底上不该出现的亮内容
  light:  L < bg - 96         # 浅底上不该出现的暗内容

ratio = 异常像素数 / 边带像素总数
溢出  = ratio >= 0.003        # 0.3% ≈ 620px @1080p
```

三个设计选择：

- **全片中位数定画风与基线**，不逐帧判定：白闪/黑场单帧不会把风格带跑，浅底片里塞一个
  暗终端证据窗也不会整片翻成深底。
- **相对背景，不用绝对亮度**：`±96` 是「明显不像背景」的灰阶差。深底 bg 13.8 → 阈值 109.8，
  浅底 bg 221.3 → 阈值 125.3。
- **要求有面积**：单个噪点/水印像素不算内容溢出。

阈值来自实片标定：正常帧异常占比 `0.000–0.008%`，注入一块 40px 宽溢出矩形后 `4.57%`，
取 0.3% 作为门槛，两侧各留一个数量级以上余量。逐帧边带只缓存 256 级亮度直方图
（`hists`，5400 帧约 11MB），判定画风时**无需二次读帧**，长片 QA 不增加 IO。

## 三、实片验证（同帧对比）

| 片 | 画风 | 异常峰值 | 默认 v4 | `--legacy-edge` (v3) | 差值 |
|---|---|---|---|---|---|
| demo-hook-compound 11.43s | dark / bg 13.8 | 0.0% | **8.8** | 8.8 | 0（11 项逐项相同） |
| project-vibeflow 50s | light / bg 221.2 | 0.02% | **9.1** | 9.1 | 0（11 项逐项相同） |

**端到端注入**（不是纯单测）：取 project-vibeflow 真实 PNG 造 30 帧序列，在第 15 帧左边带
贴一块 `#0d6e63` 暗色块：

| 口径 | 结果 | 安全区 |
|---|---|---|
| 默认 v4 | `[!] 疑似内容溢出安全区：[0.47]`（异常峰值 5.029%） | 5/10 ⛔ |
| `--legacy-edge` | 0 帧报溢出 | 10/10 ✅ |
| `--v2` | 0 帧报溢出 | 10/10 ✅ |

即：v4 抓到了旧口径在真实 PNG 上完全漏掉的浅底暗色溢出，且对正常成片**分数零回退**。

## 四、兼容性与报告

| 命令 | `qa_version` | 评分 | 边缘检测 |
|---|---|---|---|
| 默认 | `v4` | v3 时长预算 | 画风感知 |
| `--legacy-edge` | `v3` | v3 时长预算 | `edge_max > 235` |
| `--v2` | `v2` | 固定阈值 | `edge_max > 235` |

`score()` 逐项不动，门禁线 `avg < 8 → exit 1` 不动。变化只在报告：

- `raw` 新增 `edge_bleed_count`（**全量帧数**）、`edge_mode` / `edge_style` / `edge_bg` /
  `edge_delta` / `edge_area` / `edge_anomaly_max`；
- `edge_bleed` 仍是「前 10 个时间戳」以兼容 `review.mjs`，但评分改用 `edge_bleed_count`，
  不再被 `[:10]` 显示截断误导；
- 顶层 `edge` 块给外部消费；`review.mjs` 的 QA 汇总卡会显示
  「边缘 style-aware / light / 溢出 N 帧」，评审时一眼看出口径。

stdout 也直接打印口径，例如：

```
边缘检测：v4 画风感知（画风 light / 背景 221.2 / 阈值 ±96 / 面积门槛 0.3% / 异常峰值 0.02%）
```

## 五、回归夹具

`pipeline/qa/test_edge_v4.py` —— 纯合成帧，不依赖成片 / Chrome / ffmpeg，0.3 秒跑完，
已接入 `.github/workflows/ci.yml`：

1. 深底正常帧（含零散亮点）不报；
2. 浅底正常帧（暗角 + 零散深色像素）不报；同帧去掉暗角交给 legacy 必然误报；
3. 深底纯白溢出：v4 与 legacy 都报；
4. **深底中灰溢出（L=140）：legacy 漏检，v4 报**；
5. **浅底暗色溢出：legacy 的 `edge_max` 不变、漏检，v4 报**；
6. 画风分界 127.9/128.0 正确；单个噪点被面积门槛滤掉；
7. 多帧序列只报真正溢出的那一帧，画风不逐帧翻转。

```bash
python pipeline/qa/test_edge_v4.py
```

## 六、纪律

- **不要再用「把边缘亮度压到 235 以下」来过闸**。浅底暗角是视觉设计，不是 QA 补丁；
  暗角加多加少都不该影响安全区得分。
- 调 `EDGE_DELTA` / `EDGE_AREA` 必须同时跑：① `test_edge_v4.py` 全绿；
  ② demo-hook-compound 与 project-vibeflow 两条实片 v4 / `--legacy-edge` 同帧对比分数不回退。
- 新画风（非深非浅、强渐变背景）入库前，先看报告里的 `edge_style` 与 `edge_anomaly_max`：
  若正常帧异常峰值逼近 0.3%，说明画风基线不适用，要在文档里记录新口径而不是偷偷放水。
